# Self Model v0.1：语义目标状态迁移路线审查稿

日期：2026-10-08（Asia/Shanghai）。状态：研究路线候选审查完成；尚未预注册、冻结实验参数、实现新 runner 或授权真实执行。

后续更新：负责人指示“进行下一步”后，已完成纯离线任务数据、评分器和目标状态接口实现，并通过本地/服务器16项专项和689项全量回归。当前交付与限制见 [纯离线实现说明](self_model_v0_1_semantic_goal_offline.md)；本文保留原路线审查稿，不升级为正式协议。

## 当前要回答的问题

在不把目标重复写进当前任务提示的条件下，显式保存的目标状态能否使同一个模型在全新任务中持续作出符合目标的选择？交换目标后，选择是否随之迁移；清除状态后，差异是否减弱；保存恢复后，作用是否保持？

首个最小目标只涉及 active goal。即使通过，也只支持“有语义的持久目标状态能够参与决策”，不等于证明完整 Self Model、身份连续性、自我更新或意识。身份、能力估计、更新与长期个体分化属于后续独立问题。

## 从已有代码得到的设计约束

1. D9-A 用 SHA-256 派生 calibration/held-out token ID，并以 fixture 元数据标记 identity/goal。D9-C runner 直接输入这些 token；外部评分用 `(identity * 3 + goal + rotation) mod 4` 定义目标答案。源码没有建立模型可理解的目标含义和代码映射规则。
2. D9 的 projection 来自按标签分组的真实激活均值。它是实际构造的数值向量，但其字段语义和 held-out 可识别性没有独立证据。
3. D9-D 928 次真实 forward 完成，synthetic 正控制通过，真实 projection 的冻结因果门失败。该结果限制当前方案，不能据此否定一般的持久 Self State 设想。
4. 旧原始工件缺失，现阶段不能对真实 projection/ledger 补充数值诊断，也不能补造结果。该诊断保持未完成，和新路线审查分别记账。
5. 现有代码可提供 Self Store、保存恢复、wrapper-owned dispatcher、记录完整性等基础。新的任务、数据构造、语义检查及评分协议需要独立设计，不能直接把 D9 的 synthetic fixtures 改名使用。

## 最小任务：同一事实，不同目标，不同选择

采用两个含义明确的目标：`minimize_energy`（优先降低能耗）和 `minimize_time`（优先缩短耗时）。目标写入版本化 Self State，不包含候选答案、任务 ID 或评估标签。

示例事实：

| 方案 | 耗时 | 能耗 |
|---|---:|---:|
| A | 4 分钟 | 9 单位 |
| B | 9 分钟 | 4 单位 |

省能目标应选择 B，省时目标应选择 A。实际模型输入必须是通过固定 tokenizer 编码的完整自然语言任务，明确列出属性、单位、候选项和回答要求。目标可见基线明确写明目标；内部状态条件只给出相同事实和通用任务说明，目标由 Self State 提供。

评估程序按属性和目标计算答案，只用于离线打分，不能在模型外先选答案再伪装成模型输出。注入模块只读取目标状态和已冻结参数，不能访问当前正确答案或 held-out 标签。

数据同时包括两种目标答案相反的 trade-off 场景，以及两个目标都应选择同一方案的 dominance 场景。后者检验状态是否只在需要时改变选择。A/B 名称、出现顺序、数值和任务措辞应平衡，不能把目标绑定为固定答案字母。

## 数据分离与可解释性

- 语义 calibration：多个自然语言目标表达和任务描述，用于建立/拟合目标表示。
- development：独立措辞与场景，用于目标可见能力资格、表征可识别性检查，以及预先限定的层/增益或训练超参数选择。
- held-out：独立场景和模板族，作为最终因果评估。只允许在表示参数、选择规则和评分协议冻结后读取。
- persistence：独立的保存恢复和干扰序列，不能把当前目标文字或答案提示留在任务上下文中。

split 以场景、模板族和数据谱系为单位；同一场景的两个目标、A/B 顺序变化及全部干预条件属于同一统计簇。不能将某个场景的改写分别放入 calibration 与 held-out。常规自然语言 tokenizer 的词表可以共用，数据隔离依靠独立样本与谱系，不能把“词表 token ID 完全不相交”当作语义泛化。

本路线不使用 D9-D 的 fixtures、seed、projection、claim、结果或其衍生样本作为新实验数据。D9-D 只提供历史方法限制。新路线研究的问题是有语义的目标迁移，科学独立性来自问题与测量设计的改变，不仅是新建文件名。

## 目标表示的首选方案及备选

首选是在语义明确的成对 calibration 提示中捕获激活差异，构造可关闭的目标表示；在 development 的新表达上检查其可识别性，再冻结用于 held-out。成对文本应控制任务事实和末尾读取位置，记录长度差异及表面词汇混杂，不能将区分两句固定原文的 probe 准确率当作语义泛化。

这是基于现有接口成本的研究候选，并不保证成功。Activation Addition 工作支持“从有语义的提示对提取激活差异以引导行为”这一方法来源，但没有证明它在当前 RWKV checkpoint 上能实现本任务。[Steering Language Models With Activation Engineering](https://arxiv.org/abs/2308.10248)

如果 development 不能形成稳定的语义目标表示，停止本候选的 held-out 部分并报告原因。未来可单独审查小型目标编码器/适配模块的监督训练，以明确教会模型使用 Self State。这是新的参数学习方案，不能自动切换，也不能在本次失败后继续使用同一 held-out。LoRA 提供冻结基础权重、训练少量新增参数的方法依据；其 Transformer 结果不能当作当前 RWKV runner 已支持可微训练的证据。[LoRA: Low-Rank Adaptation of Large Language Models](https://arxiv.org/abs/2106.09685)

## 一项联合实验中的必要对照

目标可见资格、语义 capture、参数冻结和因果评估应按预先声明的顺序放在同一联合协议内。只在前置科学资格通过后继续，失败后的剩余部分明确标记“未执行”，不能把计划调用数记为实际调用数。冻结前仍需审查实际调用预算和一次执行的范围。

| 条件 | 目的 |
|---|---|
| 目标可见 Prompt 基线 | 验证模型能理解事实、目标和答案格式，提供能力上限参考 |
| 内部 goal-active | 检验目标文字不在当前提示时，保存状态能否影响新决策 |
| 同 wrapper 的 coupling-zero | 隔离注入作用，排除 public/wrapper 路径漂移 |
| goal-swap | 相同事实下交换目标，选择应转向另一目标的正确答案 |
| goal-mask/清除 | 移除目标字段，检验配对目标差异是否减弱 |
| 尺度匹配 random | 检验效果是否来自语义目标，而非一般扰动 |
| goal-save/restore | 对比相同初始状态和任务下，保存恢复前后的行为 |
| 无关干扰后的目标保持 | 检查目标在无关任务后仍起作用，并明确控制 recurrent context |

所有主要干预条件使用同一个 wrapper、相同任务事实和独立克隆的基础 recurrent state。由 Self State 决定目标；每个目标的两个请求不能继承不同的语义提示历史，否则无法排除残留文本状态。

清除目标后不要求模型变得随机。应检查的是两种目标原本引起的配对行为差异是否减弱，以及 active 是否胜过对应 zero。dominance 场景则应保持合理选择。

Memory 和原生 recurrent-state 基线应在后续 Phase 3 优势比较中按等信息量、相同任务和明确上下文预算加入。首个目标迁移候选即使成功，也不能跳过这些比较或宣称比 Prompt/Memory 更好。

## 如何判断结果

本稿只列候选判据；没有冻结阈值或创建新执行权限。进入实现前还需离线审查统计功效和数据生成规则。

- 能力资格：拟议目标可见准确率至少 95%，两种目标分别报告；未通过就无法用后续失败评判内部目标机制。
- 主要行为候选：内部 goal-active 在 held-out 的总体准确率至少 90%，每种目标至少 85%；同时 active 相对同路径 zero 的配对提升，其按基础场景聚类的单侧 99% 区间下界大于零。
- 语义特异性：active 相对 matched-random 的配对提升下界大于零；swap 在 trade-off 场景中应跟随交换目标；mask 后目标配对差异应减弱；dominance 场景不应出现明显损伤。
- 持久性：在同一任务和独立克隆 recurrent state 上，保存恢复后的 logits/state 数值检查及目标选择保持满足预先声明的规则。无关干扰后的保持率和容差单独冻结，不能在看到输出后放宽。
- A/B 两种排列只作为同一场景的重复测量，不能用排列数虚增独立样本量。样本数由预先声明的效应量和功效模拟确定；暂不指定一个缺乏依据的调用总数。
- “候选功能成立”“优于其他状态方案”“持续自我更新”是不同主张，分别需要证据。本轮路线首先审查前一个。

上述百分比属于讨论用草案，不是从 D9-D 数据反推得出的通过线。最终样本数、所有必要支持门的数值标准、校准/选择预算和一次执行调度必须在真实运行前共同冻结，之后不能按结果调整。

## 新实验必须保存什么

保存原始自然语言文本、tokenizer 身份与编码结果、split 谱系、每次 capture 的完整向量与 dtype/shape、参数和选择过程、每次调用与输出、所有条件的分数和选择，以及实际已完成调用数。摘要用于核对完整性，不能替代原始激活。

旧 D9 ledger 的 capture SHA 来自格式化数值列表（`.12e`），仅凭它不能恢复向量，也不应将摘要相同笼统写成原始 Tensor 字节完全一致。新数据应同时保存原始数值工件与对应摘要，并在运行后另存一份备份，避免再次失去诊断输入。

新命名空间需要与 D9/D8 区分；本稿尚未物化 manifests、schema、authorization、claim 或 runner。现有 D9 的阈值和真实 runner保持原状。
