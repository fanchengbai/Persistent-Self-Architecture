# Self Model v0.1 D4B：前瞻性稳态 OFF 等价门设计

## 1. D4 与 D4A 的离线闭环

D4 在模型加载后先用 original 路线执行一次 sequence prefix 以建立恢复态快照，
随后按六个单元顺序运行。每个单元固定 original、OFF-G1、OFF-G2，每条路线先
调用一次并丢弃输出，再调用一次计分。D4 报告没有保存任何预热输出 digest，
也没有无注入重编译 G0 路线。

D4A 只运行原失败夹具，但保存了全部调用。它显示 original 第一次和 G0 第一次
各形成独立输出簇；从第三次总调用开始，后续 original/G0 与全部 G2 共七次调用
逐位一致。original 第一次与 G0 第一次恰在 `state[4..95]` 这 92 个组件不同，
与 D4 失败位置签名相同。

需要明确：D4 确实给 OFF-G2 自己预热过一次，不能把失败简单归因于“没有预热
G2”。但 D4 没有 G0、预热输出不可观察，而 D4A 没有复现 D4 的 sequence prefix
和完整调度，因此无法把 D4 的预热/计分调用逐一映射到 D4A 的三个输出簇。两份
结果不构成直接矛盾，但现有证据不能确定具体是 CUDA 首形状、decorator/编译缓存
还是方法绑定年龄效应，也不能事后把 D4 改成通过。

## 2. D4B 只补测原失败单元

D4 的 OFF-G1 六个单元以及 OFF-G2 其余五个单元继续作为有效旧证据，不重跑。
D4B 只补测 `forward_one + state=None + full_output=false`，token 固定为 `[2764]`。
为复现 D4 上下文，先执行并记录原 sequence prefix `[187, 931]`，但不计分。

四条路线为 original、OFF-G1、G0 和 OFF-G2。先按固定顺序各调用一次，所有输出
都记录但不计分；不得根据输出追加预热或自适应等待收敛。随后执行四轮 4×4
拉丁顺序，每条路线在第一至第四位置各出现一次，共十六个计分调用。

这组预条件是一个前瞻性控制，不是已经证实的故障修复。它的作用是让四条路线
在计分前都有可审计输出，并把方法家族和顺序位置分开；不能预先宣称它会消除
D4 的差异。

每条路线四个计分输出产生六个同路线比较，四路线合计 24 个；每对路线产生
16 个跨路线比较，六对路线合计 96 个。全部 120 个比较都必须在 shape、dtype、
device 一致后满足 `torch.equal`。不得用容差、top-1 或跨运行 digest 替代。

## 3. 决策边界

D4B 失败即停止，不自动重跑或改设计。D4B 即使通过，也只形成“稳态 OFF 资格
候选”，保留 D4 原失败记录，并允许项目负责人审阅是否进入 D5；它本身不授权
D5、active injection、Self projection、真实层选择或 Self 效果实验。

当前只冻结设计。真实 runtime、机器授权、claim、模型加载、执行和结果观察均
未授权。
