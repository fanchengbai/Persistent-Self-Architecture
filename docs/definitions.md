# PSA 操作性定义与判定标准

> 版本：v0.1  
> 状态：Phase 0 设计草案，实验前需共同冻结  
> 日期：2026-07-29  
> 用途：限定项目术语、证据边界和实验准入条件。本文定义是工程定义，不是哲学或意识定义。

## 1. 基本立场

PSA 研究的不是“模型是否真的有主观体验”，而是一个更窄、可检验的问题：

> 一个跨时间保存、受证据约束地更新、在决策时共同承载身份与目标约束，并对行为产生独立因果作用的内部状态，能否构成有用的 Persistent Self 候选机制？

本项目允许答案为“不能”。所有结论只适用于所测模型、任务和时间尺度。

## 2. 核心术语

### 2.1 Agent

在环境中循环执行“观察—更新状态—选择行动—接收反馈”的系统。单次文本生成器只有被放入该循环后，才是本项目意义上的 Agent。

### 2.2 World State

系统对外部环境的当前表示，包括事实、任务条件、其他实体、事件历史和未来预测。它回答“外面发生了什么”。

### 2.3 Memory

能够被保存和取回的过去信息。可分为：

- episodic memory：具体事件；
- semantic memory：抽象事实和总结；
- procedural memory：技能或策略；
- external memory：数据库、文件、向量库、提示中的摘要；
- internal memory：模型权重、缓存或 recurrent state 中保留的信息。

Memory 回答“过去有什么信息”。信息被记住，不代表它已成为 Self，也不代表决策实际使用了它。

### 2.4 Persona

系统被要求或诱导表现出的角色、风格、人物设定或人格特征。Persona 可以来自提示、微调、参数子网络或外部脚手架。

Persona 回答“应该表现得像谁”。表现一致不自动证明跨时间内部机制。

### 2.5 Self Model

系统关于自身的可用于预测和决策的模型，例如自身能力、当前目标、承诺、偏好和限制。它回答“我处于什么状态、能做什么、受什么约束”。

Self Model 可以是显式结构，也可以是分布式内部表示；它必须通过行为和干预验证，不能只靠自述判定。

### 2.6 Self State

Self Model 在时间 \(t\) 的内部状态 \(S_t\)。它至少包含一个可跨时间持续的身份锚点和一个能参与决策的目标或约束变量。

首版只允许下列字段进入核心研究：

| 更新速度 | 字段 | 含义 |
|---|---|---|
| 受保护 / 极慢 | `identity_anchors` | 个体标识、长期承诺、不可轻易改写的约束 |
| 慢 | `preferences` | 可由累积经验改变的稳定选择倾向 |
| 慢 | `capability_estimate` | 对自身能力边界的经验估计 |
| 快 | `active_goals` | 当前目标、优先级和完成状态 |
| 快 | `confidence` | 对当前判断的可校准置信度 |
| 快 | `uncertainty_conflicts` | 不确定性及目标/约束冲突 |

`values`、`emotion`、`curiosity` 和开放式人格字段暂不进入 v0.1 核心实验，避免在机制尚未成立前扩大概念范围。

### 2.7 Persistent Self 候选机制

同时满足第 4 节六项必要条件的 Self State 机制。这里的“Self”是研究标签，不是人格、主体性或意识声明。

### 2.8 Identity

使同一系统在不同时间点可被识别为同一条状态轨迹的稳定约束集合。身份不是名字或 UUID；这些只能作为身份锚点的一部分。

### 2.9 Goal

能改变行动排序、规划或资源分配的目标变量。只有说出目标但不影响选择，不算有效目标状态。

### 2.10 Preference

在多个内容等价或可比的选择中表现出的相对稳定倾向。偏好必须跨措辞、选项顺序和任务表面变化保持，并允许在充分反馈下更新。

### 2.11 Confidence 与 Capability Estimate

- `confidence`：对某一次判断正确性的估计，是快变量；
- `capability_estimate`：对一类任务能否可靠完成的长期估计，是慢变量。

二者都必须以校准和行动选择验证，例如回答、求助、检索、继续推理或拒答，不能只测“会不会说不知道”。

### 2.12 Self Evolution

Self State 根据带来源的经验，从 \(S_t\) 更新为 \(S_{t+1}\) 的过程。有效更新必须有证据、字段级速率约束、变更记录和回滚能力。

## 3. Self、Memory、Persona 与 World State 的边界

| 机制 | 主要对象 | 典型载体 | 持续是否充分 | 因果干预是否必要 | PSA 中的角色 |
|---|---|---|---|---|---|
| World State | 外部世界 | 上下文、环境状态、内部表示 | 否 | 是 | 必要输入，不是 Self |
| Memory | 过去信息 | 文档、向量库、摘要、hidden state | 否 | 是 | 必须设置的替代解释 |
| Persona | 表现风格或角色 | Prompt、微调、参数子网 | 否 | 是 | 必须比较的行为基线 |
| Self Model | 系统自身及其约束 | 显式 schema 或内部表示 | 否 | 是 | 候选机制 |
| Persistent Self | 跨时、个体化、可更新且因果有效的 Self Model 状态 | 可保存和干预的内部状态 | 是 | 是 | 项目最终检验对象 |

一个状态即使包含全部历史，也可能只是 Memory；一个角色即使十分一致，也可能只是 Persona。只有当状态在决策时实际约束行为，并通过必要对照排除这些解释，才可升级为 Persistent Self 候选。

## 4. Persistent Self 候选的六项必要条件

### C1 持续性（Persistence）

状态在任务切换、干扰和会话边界后仍保留可测影响；影响不能只来自当前提示中的重复描述。

### C2 个体分化（Individuation）

相同模型和初始状态经不同经历后形成可区分轨迹；差异在新任务上仍可预测，而非只复述经历文本。

### C3 因果效力（Causal Efficacy）

固定模型、任务和输入，只交换、消融、插值或恢复 Self State 时，目标行为按预注册方向变化。

### C4 受约束可塑性（Constrained Plasticity）

允许更新的字段会响应充分证据，受保护字段不会被单次提示任意改写。系统能区分合理适应与无证据漂移。

### C5 决策时绑定（Decision-time Binding）

多个 Self 约束必须能在同一次决策中共同起作用。分别记住身份 A 和目标 B 只是 weak persistence；需要同时应用 A+B 才算 strong persistence。

### C6 可审计与可恢复（Auditability and Recovery）

每次状态变更可追溯到来源、版本和理由；恢复历史快照后，对应行为也应可重复恢复。

缺少任一条件时，只报告已满足的较弱现象，不使用完整的 Persistent Self 候选表述。

## 5. 排除规则

出现以下结果时，必须采用右侧较弱解释：

| 观察 | 结论上限 |
|---|---|
| 删除 Persona Prompt 后效应消失 | Persona scaffold |
| 等信息量 Memory 能完全复现效应 | Memory-based agent |
| probe 准确但干预无效 | 可读的相关表示 |
| state swap 后行为不随来源迁移 | 非因果或干预无效的状态差异 |
| 只能自述身份，选择行为不变 | narrative identity |
| 只在紧邻历史时有效，干扰后迅速消失 | short-context residue |
| 干预改变所有任务并破坏通用能力 | 非特异性模型损伤 |
| A、B 单独有效但联合决策失败 | weak persistence，而非 strong persistence |

## 6. 证据等级与命名

| 等级 | 最低证据 | 可使用措辞 |
|---|---|---|
| E0 | 自我描述 | “生成了身份/目标叙述” |
| E1 | 跨模板行为一致 | “观察到稳定行为模式” |
| E2 | probe 或重建成功 | “状态携带可读信息” |
| E3 | swap / ablation / interpolation 有特异性效应 | “状态对行为有因果贡献” |
| E4 | termination / recovery 和纵向 fork / rollback 成立 | “存在持续且可恢复的候选机制” |
| E5 | 同时满足 C1–C6，并优于等信息量 Prompt 与 Memory | “Persistent Self 候选机制” |

论文标题、摘要和 README 中的主张不得超过已达到的证据等级。

## 7. Self State 更新规则

每次更新至少记录：

```text
state_version
field
old_value
new_value
evidence
evidence_source
confidence
update_rule
timestamp_or_step
parent_state
```

更新遵循：

1. 字段专属速率：快、慢、受保护字段使用不同证据阈值。
2. 最小改动：只更新被证据直接支持的字段。
3. 来源隔离：外部事实、用户要求和系统自身经验不得混为一类。
4. 冲突保留：证据不足时记录冲突或不确定性，不强行覆盖旧状态。
5. 可逆：保留父版本和变更理由，支持 rollback。
6. 不自证：Self State 中的文字不能作为 Self State 正确性的唯一证据。

## 8. 核心假设与定义映射

| 假设 | 对应条件 | 最低证据 |
|---|---|---|
| H1：state 中可读出身份/目标信息 | C1、C2 的前置线索 | E2 |
| H2：state 对行为有因果作用 | C3 | E3 |
| H3：优于 Prompt / Memory | 排除替代解释 | E5 的必要部分 |
| H4：不同经历形成不同轨迹 | C2、C4 | E4 |
| H5：稳定性与可塑性平衡 | C4、C6 | E4 |
| H6：能力估计改善元认知行动 | C3、C4 | E3–E4 |

H1 成立而 H2 失败时，项目只能声称 state 含有相关信息。H1/H2 成立而 H3 失败时，不能声称 Self 机制具有独立价值。

## 10. 当前明确不主张

PSA v0.1 不主张：

- 系统具有意识、感受、主体性或道德地位；
- 稳定 Persona 等于身份机制；
- 长期 Memory 等于 Self；
- probe 读出等于模型实际使用；
- 一个成功的 state swap 足以证明一般性人工自我；
- 合成任务结果可以直接推广到开放域 Agent。
